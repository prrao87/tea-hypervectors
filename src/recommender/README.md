# Tea preference recommender

This directory contains the personal preference online learner based on HDC.
This is a form of machine learning in HDC that can develop an associative memory
based on seen data. Unlike traditional representation-based machine learning,
this form of learning in HDC is very sample-efficient and sort of resembles experiential
memory as seen in humans.

This learner uses the same tea hypervectors that have already been created by the encoder,
without running or changing the encoder in any way.

## The "prototype"

Each tea is represented by its own hypervector generated by the encoder. The intuition is that
teas with similar properties have hypervectors that point in similar directions in high-dimensional space.

The key component that does online learning is called a "prototype." In HDC, a prototype is a single summary
hypervector built by combining several example hypervectors. It represents what
those examples have in common, rather than any single tea in and of itself.

The recommender reads your tasting history and builds two summaries:

- A positive summary from teas you liked.
- A negative summary from teas you disliked.

Teas marked `neutral` do not affect either summary, but they are remembered as
"already tried".

Every untried tea is compared with both summaries. A tea receives a higher
score when it resembles the positive summary. It receives a small penalty when
it resembles the negative summary.

## How the math works

Every tea hypervector already has 10,000 dimensions. Before learning, we
rescale each vector so its Euclidean norm (its geometric magnitude) equals 1:

$$
\mathbf{x}_i = \frac{\mathbf{h}_i}{\lVert \mathbf{h}_i\rVert}
$$

This does not change the 10,000 dimensions or the vector's direction. It only
removes differences in magnitude. A tea with more populated data fields can
otherwise have a larger norm and cast a louder vote, simply because it contains richer
information about the tea in its representation.

For the teas you liked, the learner bundles the normalized hypervectors. As in
the root README, the `⊕` symbol denotes bundling; for these MAP hypervectors, it
is implemented by coordinate-wise addition. The CSV's `strength` value is the
weight $w_i$:

$$
\mathbf{S}^+
= w_1\mathbf{x}_1
\oplus w_2\mathbf{x}_2
\oplus \cdots
\oplus w_n\mathbf{x}_n,
\qquad \text{for the } n \text{ liked teas}
$$

It then normalizes that bundle to get the positive preference summary:

$$
\mathbf{p}^+ = \frac{\mathbf{S}^+}{\lVert \mathbf{S}^+\rVert}
$$

The negative summary $\mathbf{p}^-$ is built in exactly the same way from disliked
teas. When a new liked tea arrives, online learning is simply:

$$
\mathbf{S}^+_{\text{new}}
= \mathbf{S}^+_{\text{old}}
\oplus w_{\text{new}}\mathbf{x}_{\text{new}}
$$

There is no "retraining" pass (or backpropagation) over the tea encoder,
everything purely operates in hypervector space, using the same binding/bundling
operations that were use in the encoder. This is why the online learner
is so sample and compute-efficient.

For an untried tea $j$, the final ranking score is:

$$
\mathrm{score}(j)
= \mathbf{x}_j \cdot \mathbf{p}^+
{}- \lambda(\mathbf{x}_j \cdot \mathbf{p}^-)
$$

Because the candidate tea vector and the like/dislike prototypes are normalized
to unit norm, each dot product is equal to cosine similarity. The first term rewards resemblance to liked teas. The second term
penalizes resemblance to disliked teas, and $\lambda$ controls the size of
that penalty. The default is $\lambda=0.25$. If there are no disliked teas,
the second term is omitted.

## Input file

The tasting history lives at:

```text
inputs/preferences/tastings.csv
```

It has one row per tasting:

```csv
sequence,tea_id,title,verdict,strength,notes
1,9278958096,Ali Shan - Roasted,liked,2,"honey, caramel, floral"
```

The columns mean:

- `sequence`: the order in which you tried the teas.
- `tea_id`: the tea's identifier in the catalog.
- `title`: a readable name, also checked against the catalog.
- `verdict`: `liked`, `disliked`, or `neutral`.
- `strength`: how strongly the tea votes. A value of `2` counts twice as much
  as `1`.
- `notes`: optional human context. Notes are stored but do not affect the
  score yet.

The CSV remains the source of truth. The model is rebuilt from it each time,
which is fast for this small collection and makes every result reproducible.

## Run it

From the repository root:

```bash
uv run scripts/recommend.py
```

The command prints:

- How many tasting events were loaded.
- The total weight of liked and disliked votes.
- The highest-ranked untried teas.
- Each tea's positive and negative similarity, followed by the final score.

To request more results:

```bash
uv run scripts/recommend.py --limit 15
```

To see what the learner would have recommended after an earlier tasting:

```bash
uv run scripts/recommend.py --at-sequence 6
```

To make disliked teas count less strongly:

```bash
uv run scripts/recommend.py --negative-weight 0.1
```

The default negative weight is `0.25`. It's deliberately cautious because the
current history contains only one disliked tea.

## Files in this folder

- `events.py` reads and checks the tasting CSV.
- `catalog.py` loads the existing tea hypervectors and matches them to tasting rows.
- `prototype.py` updates the positive and negative summaries.
- `ranking.py` scores untried teas and returns the best matches.

The dependency flows in one direction: this package reads the encoded tea
catalog, while the encoder does not know anything about personal preferences.
